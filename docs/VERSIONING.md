# 版本与历史 Versioning

## 三类版本分别记录

| 版本 | 例子 | 表示什么 |
|---|---|---|
| 仓库发布基线 | v0.1.0 | 整理结构、当前状态和纳入的资料集合 |
| 方案版本 | proposal V1／V2／V3 | 研究方案的历史迭代 |
| 执行文件版本 | extended-route manual v3／form v3 | 现场执行资料，与 proposal V3 不是同一序列 |

当前仓库版本读根目录 [VERSION](../VERSION)。更新详情读 [CHANGELOG.md](../CHANGELOG.md)。Git commits 保存实际同步历史；早期讨论按文档证据保存，不伪造早期 commits。

## 更新规则

- PATCH（例如 0.1.1）：链接、文字或元数据修正，不改变研究基线。
- MINOR（例如 0.2.0）：新增里程碑资料、执行基线、分析阶段或新的重要成果。
- MAJOR：形成新的整体项目阶段或有实质重构；1.0.0 不自动表示研究已获验证。

新成果使用清晰的版本／日期目录，保留旧版。一次逻辑更新用一条有说明的 commit；同步更新 changelog、状态、决策和目录。需要里程碑快照时创建同名 Git tag／GitHub Release；只有实际创建后才对外宣称标签或 Release 已发布。
